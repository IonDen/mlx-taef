## 1. Scope + release strategy

### Items in v0.2.0

Ten work items bundled into one release, ordered by leverage:

## 2. Architecture + components

### Library code

- **`src/mlx_taef/integrations/mflux.py`** — `LivePreviewCallback.__init__` gains:
  - `flux: object | None = None` — a reference to the mflux model instance the callback will be registered on. Required for auto-bn extraction because the mflux `CallbackRegistry.register()` + `InLoopCallback.call_in_loop()` contract does NOT pass the flux instance at callback-fire time (verified against mflux 0.17.5 source). The callback must own the reference at construction.
  - `auto_bn: bool = True` — when True AND `variant="taef2"` AND `flux is not None`, extract `bn_mean = flux.vae.bn.running_mean`, `bn_var = flux.vae.bn.running_var`, `bn_eps = flux.vae.bn.eps` at init. Falls back gracefully when any attribute is missing (warn, continue with v0.1.x identity-BN behavior).
  - `callback.resolved_bn` is a tri-state: `"explicit"` (user passed `bn_mean`/`bn_var` kwargs), `"auto"` (auto-extracted from flux), `"none"` (fallback to identity). Test surface: assertion targets the tri-state.
  - Precedence: explicit kwargs > auto-extracted > none. Explicit + `auto_bn=True` is not an error — explicit wins silently.
  - Usage example: `cb = LivePreviewCallback(flux=my_flux, variant="taef2", every=5)` — `my_flux.callbacks.register(cb)` works as before; the auto-extraction already happened in `__init__`.

- **`src/mlx_taef/variants.py`** — `TaesdVariantConfig` (the frozen dataclass at `variants.py:23-49`, NOT a dict) gains a new field `memory_cap_hint_gb: int | None = None`. Defaults per variant:
  - `taesd`: None (sub-1 GB peak; no cap recommended)
  - `taesdxl`: None
  - `taef1`: 1
  - `taef2`: 2
  - New helper `get_memory_cap_hint(variant: str) -> int | None` raising `KeyError` for unknown variants. Re-exported in `mlx_taef.__init__` `__all__`.
  - Separate `FULL_VAE_CAP_GB: dict[str, int]` constant defined in `scripts/run_showcase.py` (not in the library — it's a bench harness concern): `{"flux1-dev": 6, "flux2-klein-base-4b": 12}`. Used by full-VAE baseline workers in the showcase; recorded in the report JSON for auditability.

### Tests (written first per TDD)

Test discipline: behavioral assertions, not attribute plumbing. Each test exercises real behavior end-to-end with the smallest reasonable mock surface. Mocks are at the network/model-load boundary only; library logic runs for real.

- **`tests/test_integrations_mflux.py`** adds:
  - `test_auto_bn_changes_decoded_output_vs_identity_bn` — behavioral test (mirrors existing `test_unpack_with_bn_stats_differs_from_identity_bn:73`). Feed a known latent through `LivePreviewCallback(flux=fake_flux_with_bn, variant="taef2")` and through `LivePreviewCallback(variant="taef2")` (identity BN, no flux); assert the decoded outputs differ in the expected direction (color shift on identity-BN). `fake_flux_with_bn` is a minimal stub with a real `.vae.bn` whose `running_mean/var` are known non-zero arrays — NOT a Mock; it's a tiny dataclass with the actual attribute names mflux exposes.
  - `test_auto_bn_resolved_explicit_when_bn_kwargs_passed` — pass `bn_mean=...` explicitly; assert `callback.resolved_bn == "explicit"`; assert decoded output uses the explicit values (behavioral, via a known-different bn_mean).
  - `test_auto_bn_resolved_none_when_flux_missing_vae` — `flux=object_without_vae`, `auto_bn=True`; assert `callback.resolved_bn == "none"`; assert warning emitted; assert decoded output matches the identity-BN reference.
  - `test_auto_bn_resolved_none_when_variant_not_taef2` — `flux=fake_flux_with_bn`, `variant="taef1"`; assert `callback.resolved_bn == "none"` (no-op for non-taef2).
  - `test_auto_bn_off_when_kwarg_false` — `auto_bn=False, flux=fake_flux_with_bn`; assert `callback.resolved_bn == "none"`; no extraction even when available.
  - `test_combined_uses_real_callback_registry` — replaces the originally-proposed mocked smoke. Construct a real (or minimal real-shaped) `CallbackRegistry`; register both `LivePreviewCallback` and a real `apply_teacache(flux)` handle; assert both subscribers appear in the in-loop dispatch list. Asserts the integration risk (callback-hook collision) rather than mocked plumbing. Uses `pytest.importorskip("mlx_teacache")` so it skips cleanly when the optional dep is absent.

- **`tests/test_variants.py`** adds:
  - `test_each_variant_has_memory_cap_hint_gb` — asserts the field exists on every variant config and is either `None` or a positive int.
  - `test_get_memory_cap_hint_returns_field_value` — asserts the helper returns the field for known variants.
  - `test_get_memory_cap_hint_raises_keyerror_on_unknown` — asserts the error path is explicit, not a silent None.

- **`tests/test_run_showcase.py`** NEW:
  - `test_subprocess_sentinel_first_of_line_one_per_worker` — feed canned stdout containing one valid sentinel + lines that embed the sentinel string mid-line; assert orchestrator extracts exactly the first-of-line sentinel and ignores mid-line occurrences.
  - `test_subprocess_sentinel_multiple_emits_raises` — assert worker contract violation (two sentinels) raises rather than silently picking one.
  - `test_json_schema_round_trip` — write a known result dict to a tmp file; reload; assert equal.
  - `test_json_schema_rejects_unknown_version` — load a JSON with `schema_version: 99`; assert `SchemaVersionError` (so the diff workflow doesn't silently break on schema drift).
  - `test_orchestrator_dispatch_table` — each scenario name maps to the expected worker function (drops the redundant argparse-acceptance test from the original spec; argparse validates its own choices).
  - `test_failed_rep_does_not_abort_run_parametrized` — parametrize over `(exit_code, stderr, expected_status)` rows: worker raises, exit 137 (OOM kill), exit -9 (SIGKILL/jetsam), stderr-only failure with exit 0. Assert orchestrator records each as a failure and continues.

  - DROPPED from the original spec: `test_memory_cap_applied_before_model_load` (tautological — asserted call order on a fully-mocked surface). The cap-set discipline is enforced by `test_per_condition_cap_split` above and by docstring/code review.

- **`tests/test_bench_decode.py`** NEW — same plumbing-test shape for `scripts/bench_decode.py` (sentinel parsing, JSON round-trip, decoder dispatch, failed-rep parametrized handling).

- **`tests/test_capture_latent.py`** NEW — argparse, output path resolution, `.sha256` sidecar generation (`flux.generate_image` and `mx.save_safetensors` mocked at the network boundary; output-path + sha-sidecar logic runs for real against tmp_path).

- **`tests/test_diff_showcase_report.py`** NEW — for the new `scripts/diff_showcase_report.py` tool. Asserts threshold detection (>10% wall-clock drift, >0.05 SSIM drop) flags a regression; clean diffs report no regression.

### Scripts

The `scripts/` directory does not currently exist in the repo. v0.2.0 creates it with the four scripts below.

- **`scripts/run_showcase.py`** NEW. Orchestrator. CLI:
  - `--scenario {taef2_vs_vae|taef1_vs_vae|live_preview|combined|all}`
  - `--reps N` — default 3 for full-VAE conditions; default 5 for TAEF-only conditions (TAEF decode is ~100 ms, variance from Metal kernel dispatch noise matters; full-VAE decode is ~5-15 s, 3 reps suffice). Configurable per-condition via internal default table.
  - `--report path.json` (default `_artifacts/showcase_report.json`)
  - Hidden worker invocation: `--worker-mode` flag + `--worker-payload <json>` with the full worker spec (scenario, condition, rep, save_to, cap_gb). Single hidden flag avoids the public `--scenario` colliding with the worker-side parameter.
  - Dispatches per-scenario workers in subprocesses; parses `::BENCH_RESULT::<json>` sentinels (line-start, exactly one per worker, JSON one-liner — contract pinned in code + tested); aggregates into the report JSON.
  - Computes SSIM **in the orchestrator** after both `vanilla.webp` and `taef*.webp` are saved to disk. Cross-process MLX output is not bit-stable (gotcha #24), so SSIM is computed once per (TAEF rep, full-VAE rep) pair and reported as a per-rep array + median, not a single number.

- **`scripts/_capture_latent.py`** NEW. One-shot helper. Generates one fixed-seed latent per variant; saves to `tests/fixtures/showcase_latents/<variant>.safetensors`; emits a `.sha256` sidecar. Wall-clock ETAs (M1 Max, quantize=4): FLUX.1-dev ~1-2 min, FLUX.2 klein-base-4b ~7-10 min (revised from the original ~5 min estimate).

- **`scripts/bench_decode.py`** NEW. Focused decoder bench (TAEF vs Full VAE). Loads a saved latent; decodes through both paths in separate subprocesses; reports timings + peak memory. Subprocess-per-rep. Used by `run_showcase.py` for `taef*_vs_vae` scenarios and standalone for regression-tracking.

- **`scripts/diff_showcase_report.py`** NEW. Machine-enforced regression checker. Reads two `_artifacts/showcase_report.json` files (old + new), compares per-condition median wall-clock and SSIM. Exits non-zero if any condition's `median_seconds` drifts > 10% or SSIM drops > 0.05. Reproducible alternative to "diff against the committed JSON" folklore.

### Worker timing window (canonical sequence, all decoder workers)

```python
# Module top — BEFORE any model load
mx.set_wired_limit(<cap from variant META or FULL_VAE_CAP_GB>)
mx.set_memory_limit(<cap + 2 GB>)

# In the worker function
model = load_model(...)
latent = mx.load(fixture_path)
mx.eval(latent)                           # materialize input

_ = model.decode(latent)                  # warm-up (untimed)
mx.eval(_)                                # complete warm-up kernels

# GPU flush before timing window starts.
# Without this, reset_peak_memory captures the tail of warm-up.
mx.eval(mx.zeros(1))                      # explicit barrier
mx.reset_peak_memory()

# Timed window
mx.eval(latent)                           # re-anchor input (cheap; already materialized)
t0 = time.perf_counter()
output = model.decode(latent)
mx.eval(output)                           # force completion before stopping clock
t1 = time.perf_counter()
peak_gb = mx.get_peak_memory() / 1024**3

# Save output (out of timing window)
save_webp(output, save_to)

# Emit sentinel — line-start, one per worker, JSON one-liner
print(f"::BENCH_RESULT::{json.dumps({...})}")
```

### Per-scenario data flow

| Scenario | Heavy gens | Decoder reps | What's measured |
|---|---|---|---|
| `taef2_vs_vae` | 0 (uses saved latent) | 3 × Full VAE + 5 × TAEF2 | decode latency, peak memory, SSIM(TAEF2 vs Full VAE) per (TAEF rep, VAE rep) pair |
| `taef1_vs_vae` | 0 (uses saved latent) | 3 × Full VAE + 5 × TAEF1 | same shape |
| `live_preview` | 2 × FLUX.2 gen (with + without callback) | preview every-N | total gen time delta, callback overhead, frame gallery |

### Per-condition cap policy (critical post-audit fix)

The original spec applied the variant memory cap uniformly — a TAEF2 worker capped at 2 GB and a full-VAE worker also capped at 2 GB. The full-VAE workload on FLUX.2 Klein peaks at ~9.6 GB (per README baseline); a 2 GB cap kills it before measurement. Fix: split the cap by **condition**, not by scenario.

| Condition | Cap source | Default |
|---|---|---|
| `taef2` (TAEF2 decoder) | `get_memory_cap_hint("taef2")` | 2 GB |
| `taef1` (TAEF1 decoder) | `get_memory_cap_hint("taef1")` | 1 GB |
| `vanilla_vae` (Full FLUX.2 VAE on Klein latent) | `FULL_VAE_CAP_GB["flux2-klein-base-4b"]` | 12 GB |
| `vanilla_vae` (Full FLUX.1 VAE on dev latent) | `FULL_VAE_CAP_GB["flux1-dev"]` | 6 GB |
| `live_preview` worker (full Flux gen + TAEF preview) | max(flux variant cap, taef2 hint) | 22 GB (Klein) |
| `combined` worker (full Flux gen + TAEF preview + mlx-teacache) | max(flux variant cap, taef2 hint) | 22 GB |

Each worker records its applied cap in the report JSON under `applied_cap_gb` so the comparison is auditable. The `--cap-gb override` flag on `run_showcase.py` lets users widen any cap when their hardware differs.

### Worker flow (decoder scenarios) — see Section 2 "Worker timing window" for the canonical sequence

Summary:
1. Apply cap from the per-condition cap policy (above) BEFORE any model load.
2. Load model; load fixture latent; `mx.eval(latent)`.
3. Warm-up decode; `mx.eval(_)`; **explicit GPU flush** via `mx.eval(mx.zeros(1))` before the timing window starts (the audit caught this — without it, `reset_peak_memory` captures the tail of warm-up).
4. `mx.reset_peak_memory()`; timed decode with `mx.eval` barriers around the window; `mx.get_peak_memory()`.
5. Save webp; emit single-line `::BENCH_RESULT::<json>` sentinel with `{condition, rep, elapsed_s, peak_memory_gb, applied_cap_gb, image_path}`.
6. Exit.

### Sentinel contract (pinned)

`::BENCH_RESULT::<json>` must be:
- **Line-start** (column 0). The parser uses `line.startswith("::BENCH_RESULT::")`.
- **Exactly one per worker.** Multiple sentinels raise a contract violation in the orchestrator (caught by `test_subprocess_sentinel_multiple_emits_raises`).
- **JSON one-liner.** No embedded newlines; the JSON object closes on the same line.
- Any debug `print` that includes the literal `::BENCH_RESULT::` somewhere mid-line will be ignored by the parser. The contract is documented in worker docstrings.

### Measurement discipline ("real timings, real improvements")

- **Subprocess-per-rep** (not per-condition) for genuine cold-start timing — every (scenario, condition, rep) gets a fresh Python interpreter; no warm allocator leak from prior reps. Bumped from the original 3 reps to **5 reps for TAEF-only conditions** (decode is ~100 ms, per-rep variance from Metal kernel dispatch noise dominates if reps are too few). Full-VAE conditions stay at 3 reps (decode is ~5-15 s; 3 reps amortize the startup overhead).
- **Memory caps applied before model load** — `mx.set_wired_limit` per worker, split by condition (see "Per-condition cap policy" above). `tests/conftest.py` session-level cap also installed for the test suite (mlx-teacache pattern).
- **`mx.eval` sync barriers** around every timing window — anchor the lazy graph at known points; never time graph construction. Explicit barrier between warm-up and `reset_peak_memory` so the peak captured belongs to the timed window only (post-audit fix).
- **Warm-up + 3-5 reps** — first call always pays compile + allocator init; the report includes median + min + max + **raw per-rep arrays** for both timing AND peak memory so variance is visible. Single-value reporting was the original mistake.
- **Peak memory reset** before each timed window — captures the high-water mark of that operation only.
- **SSIM as a measured distribution** — TAEF and Full VAE outputs come from separate subprocesses. Per gotcha #24, MLX output across processes is not bit-stable. The orchestrator reads both saved webps and computes SSIM for each (TAEF rep, VAE rep) pair, reporting `ssim_per_pair: [...]` and `ssim_median`. Threshold check (0.75) is on the median; the raw array exposes variance for reviewers.
- **Same input latent for cross-condition comparison** — TAEF and Full VAE decode the exact same `.safetensors` latent so SSIM measures decoder difference, not input difference.
- **Version fields via `importlib.metadata.version()`** — `mlx_taef`, `mlx_teacache`, `mflux` versions in the report JSON are looked up at runtime, not hand-coded. Prevents version-string drift from the actual installed package.

## 4. Error handling + failure modes

### Worker subprocess crashes (OOM, model load failure, etc.)

Orchestrator captures exit code + stderr; failed reps recorded as `{"rep": N, "error": "<stderr tail>"}` in the JSON. One failed rep doesn't kill the run. If ALL reps for a condition fail, the condition is marked `"status": "failed"` and the scenario can't compute a median; orchestrator exits non-zero so CI/release flow catches it.

### Fixture latents missing or stale

`_capture_latent.py` writes both the `.safetensors` and a sidecar `.sha256` file. `run_showcase.py` reads both at start; missing `.safetensors` → exit with "Run `_capture_latent.py --variant ...` first"; sha mismatch → warn + continue (latent was regenerated, that's expected, but flagged in the run log).

`tests/fixtures/showcase_latents/` is gitignored by default — committing the binary is optional. The sha pinning is the contract; the blob can be repo-local.

### SSIM below threshold

Below 0.75 → JSON records `"passed": false`; orchestrator emits a WARNING but does not exit non-zero. This is a quality signal, not a hard failure — TAEF has known regimes where SSIM dips and the user should see the actual number. COMPARISON.md template includes both the SSIM value AND the threshold.

### Memory cap exceeded

Two distinct failure modes (post-audit clarification):

**Mode A: Cap rejected at worker startup** — `mx.set_wired_limit(<cap>)` itself raises (e.g., user passed a cap > system `iogpu.wired_limit_mb`). The worker dies before it can emit a sentinel. Orchestrator sees a non-zero exit code with no sentinel; parses stderr for the MLX error message and records `{"status": "failed", "error": "wired cap rejected: <stderr>"}`.

**Mode B: Cap exceeded mid-decode** — allocation under load exceeds the wired cap. MLX raises an exception inside the worker; the worker's try/except catches it and emits a sentinel with `{"status": "failed", "error": "wired cap exceeded at N GB", "applied_cap_gb": <cap>}`. Orchestrator records and continues to next rep.

Per-condition cap split (Section 3 "Per-condition cap policy") means a worker should never see Mode B for the canonical recipes — Klein-9B never fits in 2 GB. The split is the fix; Mode B should only fire when `--cap-gb override` is set too aggressively. The variant META cap can be overridden via `--cap-gb` if a workload genuinely needs more.

### Optional dependency missing

- `mlx_teacache` not installed: combined-scenario worker raises a clear `MlxTeacacheNotInstalledError`; orchestrator records `"status": "skipped", "reason": "mlx_teacache not installed"`; scenario marked skipped (not failed); `run_showcase.py --scenario combined` exits 0 with a clear message.
- `mflux` not installed: live-preview + combined + both `*_vs_vae` scenarios all skip the same way (Full VAE needs mflux too).

### Auto-bn extraction edge cases

| Condition | Behavior |
|---|---|
| `variant != "taef2"` | Auto-bn is a no-op. |
| `flux.vae` missing | Log warning "auto_bn=True but flux instance has no .vae attribute; previews will be color-shifted"; continue with v0.1.x behavior. |
| `flux.vae.bn` missing | Log warning; fall back. |
| `flux.vae.bn.running_mean / running_var` shape unexpected | Log warning; fall back. |
| Explicit `bn_mean=...` kwarg passed AND `auto_bn=True` | Explicit wins; no warning. Documented in the docstring. |

Each fallback path has a dedicated unit test asserting (a) no crash, (b) warning emitted, (c) callback still produces *some* preview output.

### Calibration regression detection ("verify and calibrate")

`_artifacts/showcase_report.json` is committed at v0.2.0 release time with the bench-run numbers. Future re-runs produce a fresh JSON; reviewers run `scripts/diff_showcase_report.py old.json new.json --tolerance 10%` (new in v0.2.0) for a machine-enforced regression check. The tool flags any condition whose `median_seconds` drifts > 10% or whose `ssim_median` drops > 0.05. Exits non-zero if any drift detected, so it can be wired into a future CI workflow. Per-rep raw arrays are preserved so reviewers can see variance, not just summary stats.

Schema versioning: `schema_version: 1` is checked at load time; loading a JSON with an unknown version raises `SchemaVersionError` rather than silently misinterpreting fields. Future schema bumps add a `2`-to-`1` adapter rather than mutating field names in place.

### Honest-claim discipline

COMPARISON.md table cells reference the exact JSON path: e.g., "100 ms ([report](_artifacts/showcase_report.json))". Every claim in COMPARISON.md ties to a measurement in the committed JSON. README's "~100 ms" claim gets replaced with the actual measured number from the JSON (or a range like "70-130 ms across 3 reps"). No hand-waved performance numbers in v0.2.0+ docs.

## 5. Testing strategy

### TDD loop per `superpowers:test-driven-development`

For every code change:

1. Write the failing test.
2. Run pytest → confirm specific assertion fails.
3. Write minimal implementation.
4. Run pytest → confirm it passes.
5. Refactor if obvious; tests stay green.
6. Commit (test + impl together).

Each task in the implementation plan is one TDD cycle. Bigger features (auto-bn, run_showcase orchestrator) split into multiple cycles.

**Dropped from the original spec:**
- `test_argparse_accepts_all_scenarios` — testing argparse, not the codebase.
- `test_memory_cap_applied_before_model_load` — tautological on a fully-mocked surface; replaced by `test_per_condition_cap_split` which tests the actual policy.

### Pytest markers

- Default CI run: `pytest -m "not slow and not network and not benchmark and not gpu"` — all new plumbing tests.
- `tests/test_perf.py` keeps its existing role (no marker by default; runs in CI as the in-process perf sanity check).
- `scripts/run_showcase.py` is NOT a pytest test — runs locally on demand.

### Coverage target

100% line + branch coverage on the new code (matches mlx-taef's existing standard). Mocked MLX paths still count — the dispatch / orchestration logic is the unit of behavior under test; MLX heavy lifting is integration-level, covered by the bench run. `# pragma: no cover` only on the categories the python-ml-testing rubric allows.

### Mock-vs-real boundary

Tests run in milliseconds, never touch the GPU, never load real weights. The bench script is exercised end-to-end by the user running it (once at release time, occasionally for regression checks). Matches mlx-teacache's pattern where `scripts/bench_speedup.py` has plumbing tests but no integration test in CI.

For the combined-use smoke test specifically: mock flux instance with `.generate_image()` that calls registered callbacks N times; mock `apply_teacache` returning a fake handle with settable `.stats.skipped_count`; assert both wrappers' state changed across N steps with no exception. Cost: <1s. Real integration test for combined-use would be ~30 min of GPU time; that's covered by `run_showcase.py --scenario combined` instead.

### What the bench run validates beyond the test suite

| Validation | Test suite | Bench run |
|---|---|---|
| auto-bn extracts from real flux instance | ⚠️ mocked | ✅ real (combined scenario uses real flux) |
| Decoder timing is honest | — | ✅ subprocess-per-rep with warm-up + 3 reps |
| Peak memory under variant cap | — | ✅ recorded per worker |
| SSIM ≥ threshold | — | ✅ measured + recorded |
| Both wrappers coexist without error | ✅ mocked smoke | ✅ real (combined scenario) |
| Image quality (perceptual) | — | ✅ committed webp images for visual review |

### Test commit cadence

One commit per TDD cycle (test + impl). Roughly 10-12 commits on the branch, mirroring the implementation plan structure. Each commit's tests pass independently — bisect-friendly.

## Out of scope (explicit non-goals for v0.2.0)

- Automated regression detection in CI. `scripts/diff_showcase_report.py` is the manual checker; wiring it into a CI workflow is a future item.
- Cross-chip bench coverage (M3/M4/M5) — community PRs invited via the protocol in COMPARISON.md.
- **TAESD3 and TAESANA support.** Both are confirmed present in upstream `madebyollin/taesd` (README variant table, as of 2026-05-26). Adding either requires its own integration + calibration cycle; deferred from v0.2.0 and documented in ROADMAP as known-upstream-but-not-yet-supported (not as "hypothetical future variants").
- Calibration of TAEF2 against newer FLUX.2 weights (TAEF2 ships against FLUX.2 Klein; other FLUX.2 weights may need their own validation — future concern).
- `decode_streaming()` API (ROADMAP entry only).
- JPEG XL output from `decode_image()` (ROADMAP entry only).
