# mlx-taef v0.2.0 — Design

**Status:** Approved 2026-05-26.
**Target release:** v0.2.0 (single cohesive release; tag held until showcase bench is run).
**Scope:** Library improvements + a measured, honest showcase that demonstrates the library's claims with committed images and a reproducible JSON report.

---

## 1. Scope + release strategy

### Items in v0.2.0

Nine improvements bundled into one release, ordered by leverage:

1. **`LivePreviewCallback` auto-bn extraction** for `taef2` (opt-out via `auto_bn=False`).
2. **`COMPARISON.md` + `scripts/run_showcase.py`** — the showcase (4 scenarios).
3. **Combined-use smoke test** — TAEF preview + `apply_teacache` registered on the same mflux instance, asserted to coexist.
4. **`scripts/bench_decode.py`** — subprocess-per-rep decoder bench, separate from the showcase orchestrator.
5. **Per-variant `META["memory_cap_hint_gb"]`** mirroring the mlx-teacache pattern.
6. **`ROADMAP.md`** — externalize the project's direction.
7. **Cross-process MLX non-determinism caveat** in `docs/manual-verification.md`.
8. **Upstream TAESD variant check** — a quick `gh api repos/madebyollin/taesd/releases` poll; any new variant becomes a deferred work item documented in `ROADMAP.md`.
9. **`pyproject.toml` Trove classifiers** alignment with mlx-teacache.

### Release strategy: Approach C — hold the tag

All work lands on `feature/v0.2.0` as a DRAFT PR. The user runs the showcase + bench on their own schedule. When numbers land, the PR un-drafts, gets merged, and v0.2.0 is tagged in one cohesive release.

Today's deliverable: all code + tests + bench scripts + COMPARISON.md skeleton + CHANGELOG entry. Zero MLX heavy generation runs today. The branch is fully prepped so running the bench is one command later.

## 2. Architecture + components

### Library code

- **`src/mlx_taef/integrations/mflux.py`** — `LivePreviewCallback.__init__` gains `auto_bn: bool = True`. When True and `variant="taef2"`, the callback walks the registered flux instance for `.vae.bn.running_{mean,var}` and applies them. Falls back gracefully when any attribute is missing (warn, continue with v0.1.x behavior). The resolved values are exposed via `callback.resolved_bn` for test assertions. Explicit `bn_mean=...` and `bn_var=...` kwargs win over auto-extraction.

- **`src/mlx_taef/variants.py`** — each variant META dict gains `"memory_cap_hint_gb"`:
  - `taesd`: None (sub-1 GB; no cap recommended)
  - `taesdxl`: None
  - `taef1`: 1
  - `taef2`: 2
  - New helper `get_memory_cap_hint(variant: str) -> int | None`.

## 3. Data flow + measurement discipline

### End-to-end showcase run (later, on the user's schedule)

```bash
# Step 1: refresh fixture latents (heavy; one-time per variant)
uv run python scripts/_capture_latent.py --variant flux1-dev              # ~70 s
uv run python scripts/_capture_latent.py --variant flux2-klein-base-4b    # ~5 min

# Step 2: run all 4 scenarios
uv run python scripts/run_showcase.py --scenario all --reps 3 \
    --report _artifacts/showcase_report.json
# Wall-time: ~30–40 min on M1 Max

# Step 3: commit produced images + JSON; fill in COMPARISON.md tables; tag v0.2.0
```

### Per-scenario data flow

| Scenario | Heavy gens | Decoder reps | What's measured |
|---|---|---|---|
| `taef2_vs_vae` | 0 (uses saved latent) | 3 × Full VAE + 3 × TAEF2 | decode latency, peak memory, SSIM(TAEF2 vs Full VAE) |
| `taef1_vs_vae` | 0 (uses saved latent) | 3 × Full VAE + 3 × TAEF1 | same shape |
| `live_preview` | 2 × FLUX.2 gen (with + without callback) | preview every-N | total gen time delta, callback overhead, frame gallery |
| `combined` | 1 × FLUX.2 gen (both wrappers) | preview every-N | total time, TeaCache stats, frames + final image |

### Worker flow (decoder scenarios)

1. `mx.set_wired_limit(<from variant META>)` + `mx.set_memory_limit(<wider>)` at module top, BEFORE any model load.
2. Load model; load fixture latent from safetensors; `mx.eval(latent)` to materialize the input.
3. One warm-up decode (untimed).
4. `mx.reset_peak_memory()`; `mx.eval(input)`; `t0 = perf_counter()`; decode; `mx.eval(output)`; `t1 = perf_counter()`; `peak = mx.get_peak_memory()`.
5. Save webp; emit `::BENCH_RESULT::<json>` with `{condition, rep, elapsed_s, peak_memory_gb, image_path}`.
6. Exit.

### Measurement discipline ("real timings, real improvements")

- **Subprocess-per-rep** (not per-condition) for genuine cold-start timing — every (scenario, condition, rep) gets a fresh Python interpreter; no warm allocator leak from prior reps.
- **Memory caps applied before model load** — `mx.set_wired_limit` per worker, derived from variant META; conftest.py session-level cap also installed for the test suite (mlx-teacache pattern).
- **`mx.eval` sync barriers** around every timing window — anchor the lazy graph at known points; never time graph construction.
- **Warm-up + 3 reps minimum** — first call always pays compile + allocator init; the report includes median + min + max + raw per-rep values so variance is visible.
- **Peak memory reset** before each timed window — captures the high-water mark of that operation only.
- **SSIM thresholded at 0.75** for TAEF vs Full VAE (lossy by design per the python-ml-testing rubric).
- **Same input latent for cross-condition comparison** — TAEF2 and Full VAE decode the exact same `.safetensors` latent so SSIM is honest.

## 4. Error handling + failure modes

### Worker subprocess crashes (OOM, model load failure, etc.)

Orchestrator captures exit code + stderr; failed reps recorded as `{"rep": N, "error": "<stderr tail>"}` in the JSON. One failed rep doesn't kill the run. If ALL reps for a condition fail, the condition is marked `"status": "failed"` and the scenario can't compute a median; orchestrator exits non-zero so CI/release flow catches it.

### Fixture latents missing or stale

`_capture_latent.py` writes both the `.safetensors` and a sidecar `.sha256` file. `run_showcase.py` reads both at start; missing `.safetensors` → exit with "Run `_capture_latent.py --variant ...` first"; sha mismatch → warn + continue (latent was regenerated, that's expected, but flagged in the run log).

`tests/fixtures/showcase_latents/` is gitignored by default — committing the binary is optional. The sha pinning is the contract; the blob can be repo-local.

### SSIM below threshold

Below 0.75 → JSON records `"passed": false`; orchestrator emits a WARNING but does not exit non-zero. This is a quality signal, not a hard failure — TAEF has known regimes where SSIM dips and the user should see the actual number. COMPARISON.md template includes both the SSIM value AND the threshold.

### Memory cap exceeded

`mx.set_wired_limit` raises → worker catches → sentinel reports `"error": "wired cap exceeded at N GB"`. Orchestrator records and moves on. The variant META cap can be overridden via `--cap-gb` on the orchestrator if a workload genuinely needs more.

### Optional dependency missing

- `mlx_teacache` not installed: combined-scenario worker raises a clear `MlxTeacacheNotInstalledError`; orchestrator records `"status": "skipped", "reason": "mlx_teacache not installed"`; scenario marked skipped (not failed); `run_showcase.py --scenario combined` exits 0 with a clear message.
- `mflux` not installed: live-preview + combined + both `*_vs_vae` scenarios all skip the same way (Full VAE needs mflux too).

### Auto-bn extraction edge cases

| Condition | Behavior |
|---|---|
| `variant != "taef2"` | Auto-bn is a no-op. |
| `flux.vae` missing | Log warning "auto_bn=True but flux instance has no .vae attribute; previews will be color-shifted"; continue with v0.1.x behavior. |
| `flux.vae.bn` missing | Log warning; fall back. |
| `flux.vae.bn.running_mean / running_var` shape unexpected | Log warning; fall back. |
| Explicit `bn_mean=...` kwarg passed AND `auto_bn=True` | Explicit wins; no warning. Documented in the docstring. |

Each fallback path has a dedicated unit test asserting (a) no crash, (b) warning emitted, (c) callback still produces *some* preview output.

### Calibration regression detection ("verify and calibrate")

`_artifacts/showcase_report.json` is committed at v0.2.0 release time with the bench-run numbers. Future re-runs produce a fresh JSON; reviewers diff against the committed one to spot regressions. Suggested workflow on a future release: re-run, diff JSON; if any condition's `median_seconds` drifts > 10% or SSIM drops > 0.05, flag for investigation. Not automated in v0.2.0 (out of scope) but the JSON schema is built for it. Per-rep raw data is preserved so reviewers can see variance, not just summary stats.

### Honest-claim discipline

COMPARISON.md table cells reference the exact JSON path: e.g., "100 ms ([report](_artifacts/showcase_report.json))". Every claim in COMPARISON.md ties to a measurement in the committed JSON. README's "~100 ms" claim gets replaced with the actual measured number from the JSON (or a range like "70-130 ms across 3 reps"). No hand-waved performance numbers in v0.2.0+ docs.

## 5. Testing strategy

### TDD loop per `superpowers:test-driven-development`

For every code change:

1. Write the failing test.
2. Run pytest → confirm specific assertion fails.
3. Write minimal implementation.
4. Run pytest → confirm it passes.
5. Refactor if obvious; tests stay green.
6. Commit (test + impl together).

Each task in the implementation plan is one TDD cycle. Bigger features (auto-bn, run_showcase orchestrator) split into multiple cycles.

### Test surface

| Test file | New tests | What's mocked | TDD-able? |
|---|---|---|---|
| `tests/test_integrations_mflux.py` | 5 auto-bn tests + 1 combined-use smoke | Mock flux instance; mock `mlx_teacache` handle | ✅ |
| `tests/test_variants.py` | 1 META field test | None (pure-data assertion) | ✅ |
| `tests/test_run_showcase.py` NEW | argparse, sentinel parsing, JSON round-trip, dispatch, memory-cap call order, failed-rep handling | `mx.set_wired_limit`, `taef.from_pretrained`, `flux.generate_image`, `subprocess.run` | ✅ |
| `tests/test_bench_decode.py` NEW | argparse, sentinel parsing, JSON round-trip, decoder dispatch | Same as above | ✅ |
| `tests/test_capture_latent.py` NEW | argparse, output path, sha256 sidecar | `flux.generate_image`, `mx.save_safetensors` | ✅ |

### Pytest markers

- Default CI run: `pytest -m "not slow and not network and not benchmark and not gpu"` — all new plumbing tests.
- `tests/test_perf.py` keeps its existing role (no marker by default; runs in CI as the in-process perf sanity check).
- `scripts/run_showcase.py` is NOT a pytest test — runs locally on demand.

### Coverage target

100% line + branch coverage on the new code (matches mlx-taef's existing standard). Mocked MLX paths still count — the dispatch / orchestration logic is the unit of behavior under test; MLX heavy lifting is integration-level, covered by the bench run. `# pragma: no cover` only on the categories the python-ml-testing rubric allows.

### Mock-vs-real boundary

Tests run in milliseconds, never touch the GPU, never load real weights. The bench script is exercised end-to-end by the user running it (once at release time, occasionally for regression checks). Matches mlx-teacache's pattern where `scripts/bench_speedup.py` has plumbing tests but no integration test in CI.

For the combined-use smoke test specifically: mock flux instance with `.generate_image()` that calls registered callbacks N times; mock `apply_teacache` returning a fake handle with settable `.stats.skipped_count`; assert both wrappers' state changed across N steps with no exception. Cost: <1s. Real integration test for combined-use would be ~30 min of GPU time; that's covered by `run_showcase.py --scenario combined` instead.

### What the bench run validates beyond the test suite

| Validation | Test suite | Bench run |
|---|---|---|
| auto-bn extracts from real flux instance | ⚠️ mocked | ✅ real (combined scenario uses real flux) |
| Decoder timing is honest | — | ✅ subprocess-per-rep with warm-up + 3 reps |
| Peak memory under variant cap | — | ✅ recorded per worker |
| SSIM ≥ threshold | — | ✅ measured + recorded |
| Both wrappers coexist without error | ✅ mocked smoke | ✅ real (combined scenario) |
| Image quality (perceptual) | — | ✅ committed webp images for visual review |

### Test commit cadence

One commit per TDD cycle (test + impl). Roughly 10-12 commits on the branch, mirroring the implementation plan structure. Each commit's tests pass independently — bisect-friendly.

## Out of scope (explicit non-goals for v0.2.0)

- Automated regression detection in CI (the JSON schema enables it; the workflow itself is a future item).
- Cross-chip bench coverage (M3/M4/M5) — community PRs invited via the protocol in COMPARISON.md.
- New TAESD variants beyond the four already supported (deferred to a future release based on the upstream poll in item 8).
- Calibration of TAEF2 against newer FLUX.2 variants (TAEF2 ships against FLUX.2 Klein; other FLUX.2 weights may need their own validation but that's a future concern).
- `decode_streaming()` API (ROADMAP entry only).
- JPEG XL output from `decode_image()` (ROADMAP entry only).

## Success criteria

v0.2.0 ships when:

1. All 9 items in scope are implemented with tests landing in the same commit.
2. CI is green on the DRAFT PR (same checks as v0.1.x: lint, typecheck, test-pure-core, test-mflux × 3 Python versions, coverage).
3. The bench run has been executed locally; `_artifacts/showcase_report.json` is committed; COMPARISON.md tables are filled in from the JSON; `_artifacts/showcase/<scenario>/*.webp` images are committed.
4. README links to COMPARISON.md; the "~100 ms" hand-waved claim is replaced with the measured number from the JSON.
5. PR is un-drafted, reviewed, and merged into `main`.
6. v0.2.0 tag is pushed (with explicit authorization from the user, per CLAUDE.md release-flow rule); release workflow publishes the wheel to PyPI via Trusted Publishing.
